# Meshtard 0.1.3 (pre-release)

Installs itself on Linux (applications menu, icon, .skp file type), no longer crashes or freezes on damaged files, and picks faster in models with many repeated components.

## Downloads

| File | Platform | Notes |
|---|---|---|
| `meshtard-windows-x64.zip` | Windows 10/11, x64 | Unsigned: SmartScreen warns on first start ("More info" > "Run anyway"). Uses an NVIDIA GPU for picking large models when the CUDA driver and NVRTC are present, else the CPU. |
| `meshtard-macos-arm64.tar.gz` | macOS 13+, Apple silicon | Unsigned: right-click > Open the first time, or `xattr -d com.apple.quarantine meshtard`. |
| `meshtard-linux-x64.tar.gz` | Linux x64 (Vulkan or GL) | Needs a Vulkan or OpenGL driver; file dialogs use the XDG desktop portal. Unpack and run `./meshtard` once: it offers to install itself for your user (`~/.local/bin`, with an applications menu entry and icon), or use Help > Install for This User. |


## Known limits (read first)

- **Saving to .skp** keeps geometry, groups and components, tags (on faces, edges, texts and dimensions), materials and textures, guides, dimensions, text, section planes, images, style settings, units, the current view and arcs/circles. **Not saved yet:** scenes, shadow settings, fog, model axes, locks, the active section plane, two-point perspective, tag folders and dashes, environments, fonts and dimension expert settings, texts and dimensions inside groups and components.
- Files are written in the SketchUp 2017 format, which SketchUp 2017 and later open.
- On Linux the automatic Alt + drag handling has not been tried on a real Cinnamon, GNOME or MATE desktop yet; if Alt tools still move the window, set the desktop's window-move key to Super.
- No Ruby API: SketchUp extensions do not run. Meshtard has its own extension system (Rhai scripts).
- Images larger than 8192 × 8192 pixels are refused (textures, Match Photo photos).
- Not tried on real Windows or macOS hardware by hand yet; CI builds and tests on both.

## What's new since 0.1.2

## Linux

- Install for This User: started from anywhere else, Meshtard offers to install itself in `~/.local/bin` with its icon, an applications menu entry and the `.skp` file type (Install / Not now / Don't ask again), and offers again when a newer version is started; also in Help > Install for This User. Window > Preferences > General turns the question back on and uninstalls (only the files the install wrote). `meshtard --version` prints the version.

## Fixes

- Damaged or hostile files no longer crash, freeze or exhaust memory when opened or imported: every reader was fuzzed (`.skp`, IFC/STEP, DXF, glTF/GLB, OBJ, STL, PLY, FBX, 3MF, 3DS, `.style`, `.mtx`, texture images) and what it found is fixed. Examples: NaN or huge vertex coordinates in mesh files, DXF arcs with absurd angles and dimension blocks nesting each other, glTF files with accessors of the wrong type, FBX arrays and IFCZIP/3MF archives claiming gigabytes, IFC Boolean results naming the same solid at every level, FBX meshes and 3MF components copied millions of times, PLY elements with billions of empty records. Such files now give the usual "Could not open/import" message (or import without the broken parts). See `spec/FUZZING.md`.
- Images (textures, photos, watermarks, thumbnails) larger than 8192 × 8192 pixels are refused with an error instead of being decoded; a file only claiming such a size can no longer allocate gigabytes.
- Should a reader still fail unexpectedly, the error dialog explains it and the open model stays as it was, instead of the app closing.

## Performance

- Picking groups and components placed many times no longer puts every copy in world
  space: the pick index and the edge culling look into each definition's mesh in its
  own coordinates, with the same answers as before. With 10,000 placed boxes a rebuild
  after an edit is about 3.5x faster (scene 20 ms to 6 ms, pick index 27 ms to 4 ms,
  first hover 22 ms to 5 ms) and the scene's picking lists take 10 MB instead of 28 MB;
  the FIAT car's pick index builds 3.3x faster.
- Undo after a big edit was measured again on a million-edge grid: 5 to 10 ms when
  repeated, single runs anywhere from 5 to 60 ms on a shared machine (the 50 ms
  reported before was one of those); an undo right after the edit costs 20 to 30 ms,
  mostly saving the edited state for Redo. Unchanged; details in spec/PERFORMANCE.md.
