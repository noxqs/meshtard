# Meshtard 0.1.2 (pre-release)

Fixes how geometry is drawn after undoing a Move, Rotate or Scale, and makes large models lighter: repeated components share one copy on the GPU, and undo steps copy only what changed.

## Downloads

| File | Platform | Notes |
|---|---|---|
| `meshtard-windows-x64.zip` | Windows 10/11, x64 | Unsigned: SmartScreen warns on first start ("More info" > "Run anyway"). Uses an NVIDIA GPU for picking large models when the CUDA driver and NVRTC are present, else the CPU. |
| `meshtard-macos-arm64.tar.gz` | macOS 13+, Apple silicon | Unsigned: right-click > Open the first time, or `xattr -d com.apple.quarantine meshtard`. |

## Known limits (read first)

- **Saving to .skp** keeps geometry, groups and components, tags (on faces, edges, texts and dimensions), materials and textures, guides, dimensions, text, section planes, images, style settings, units, the current view and arcs/circles. **Not saved yet:** scenes, shadow settings, fog, model axes, locks, the active section plane, two-point perspective, tag folders and dashes, environments, fonts and dimension expert settings, texts and dimensions inside groups and components.
- Files are written in the SketchUp 2017 format, which SketchUp 2017 and later open.
- On Linux the automatic Alt + drag handling has not been tried on a real Cinnamon, GNOME or MATE desktop yet; if Alt tools still move the window, set the desktop's window-move key to Super.
- No Ruby API: SketchUp extensions do not run. Meshtard has its own extension system (Rhai scripts).
- Not tried on real Windows or macOS hardware by hand yet; CI builds and tests on both.

## What's new since 0.1.1

## Performance

- Groups and components placed many times are drawn with GPU instancing: one copy of each definition's faces and edges on the GPU, drawn once per instance, instead of a copy per instance. 10,000 instances of a component: 43 MB of GPU buffers down to 4.5 MB, uploads after each edit 15x faster; real files with repeated components 2-3x less GPU memory. What is drawn is unchanged.
- Undo steps now copy only the parts of a model an edit changed, even inside one huge group or the model root: after a small edit of a million-edge model, the undo step takes ~1 ms instead of ~0.14 s, and Undo ~1 ms instead of ~0.13 s. Edits on imported models no longer pause to compare the whole model first (Move on real files 5 to 50x faster).

## Fixes

- Undo after a Move, Rotate or Scale drew the restored geometry wrong: edges that met the moved entities were still drawn stretched to where the operation had put them (a box "half restored" after undoing a moved edge, then a rectangle "with the moved corner"). The model itself was restored correctly; the drawing now is too. Edit > Undo during a running Move also puts back what its preview hid.
